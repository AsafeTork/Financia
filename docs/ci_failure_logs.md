## Potential Causes

1. **Node.js version mismatch:** `package-lock.json` was generated by npm from Node.js 22; Node.js 20 ships with an older npm that may not parse the lockfile correctly
2. **Missing cache + memory limit:** The old workflow used `NODE_OPTIONS: --max-old-space-size=6144` and `actions/cache@v4` — without them, `npm ci` may run out of memory on the runner
3. **`npm ci` vs `npm install`:** The `build.yml` workflow succeeds with `node-version: '20'` using `npm install` (more lenient), while the CI uses `npm ci` (strict lockfile validation)

## Recommendation

Revert Node.js to `'22'` and restore `NODE_OPTIONS: --max-old-space-size=6144` to match the working configuration from the previous pipeline.
